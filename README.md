# AI Pod Reference Architecture — LLM Routing, Semantic Caching & Cost Modeling

A reference architecture and cost model for LLM request routing in Managed AI Pods. It includes a runnable, offline token-cost estimator and a reproducible benchmark.

> **This is a reference implementation, not a production library.** It is an example project built by a [Folder IT](https://folderit.net) AI Pod: it documents how to structure LLM request routing and cost control, and lets anyone reproduce the cost figures for themselves. Maintained as a static reference.

## What this is

- A documented **architecture blueprint** for the request lifecycle of an LLM-backed workflow: cache → route → local SLM or premium model → measure.
- A single **runnable module** — a deterministic token-cost estimator — with tests and a reproducible benchmark.
- A **cost model** you can run offline to estimate token spend under different routing strategies.

## What this is not

- Not a production framework and not middleware that intercepts live traffic.
- Not a service that calls any LLM. It runs fully offline and needs no API keys.
- Not a latency benchmark. It models **cost**, not measured wall-clock time.

Being explicit about the boundary is deliberate: the value here is a transparent, reproducible cost model, not a black box.

## The request lifecycle

The blueprint models four stages for every incoming request:

1. **Semantic cache check.** If a near-identical request was answered before, return the cached answer at zero token cost.
2. **Intent routing.** Route routine requests to a local Small Language Model (SLM) and reserve premium cloud models for requests that need heavier reasoning.
3. **Execution.** The request is handled by the selected target.
4. **Measurement.** Token consumption and estimated cost are recorded for every request.

Full diagrams and the decision records live in [`docs/architecture.md`](docs/architecture.md). In this repo, only stage-relevant **cost estimation** is implemented as code; the rest is documented as architecture.

## The runnable module: token cost estimator

The estimator is deterministic and offline. Given a set of prompts, it estimates token spend under two strategies and reports the difference:

- **Baseline** — every request goes to a premium cloud model.
- **Routed** — exact-match caching plus routing to a local SLM where the rules allow it.

It uses [`tiktoken`](https://github.com/openai/tiktoken) for token counting and a dated, sourced pricing table. Because it has no randomness and no network calls, the same input always produces the same output.

## Assumptions

This is a model, so it rests on stated assumptions. All of them are documented in [`docs/decision_records/assumptions.md`](docs/decision_records/assumptions.md). The two that matter most:

- **Local SLM cost.** Local inference is modeled at zero token cost because it runs on owned infrastructure. The real cost is compute and amortization, not per-token billing. The estimator accepts an optional per-request infrastructure cost so you can model this yourself rather than assume it is free.
- **Output tokens.** Output length per request is a declared estimate, not a measured value, since no model is actually called.
